# Decode throughput part of the pie vs vLLM gap on L4 (gpt-oss c8/c16 selects on the run kernel)

gpt-oss-20b's c8 and c16 decodes route 32 and 64 routes over its 32 experts, 1 and 2 an expert, and the L4 profile's `moe.mxfp4_mma_per_from = 4` (copied from the L40S file) kept them off the register-dequant kernels. Being under the 2-an-expert grouping threshold too, they ran the by-route `moe_matmul_select_mxfp4`, which streams an expert's codes once for each route: 0.84 ms a select, about 40 ms of a c16 step whose ITL is 50 ms (nsys). vLLM 0.32.0 runs Marlin at every width. With `= 0`, as on the A40, they take the 512-code run kernel that c25–c128 already decode on, which reads each touched expert once (0.47 ms a select). Decodes of 7–24 lanes move to it, the ones of 17–24 off the grouped wmma select. `the_routed_selects_answer_the_routed_dot` gains gpt-oss-20b's c16 gate/up select (32 experts, 16 tokens, top 4, by token under the clamped SwiGLU: 2 routes an expert, `moe_select_mxfp4_mma_run<4, 4, 3, 4>` on sm_89), where no case covered the run kernel at 2–3 routes an expert.

On an L4, 3 alternating rounds on this tree: c16 301 → 486 tok/s (vLLM 442), c8 243 → 277 (vLLM 276), c24 674 → 665 (−1.3%, below base in each round, where the grouped wmma select beat the run kernel at 3 routes an expert), and c32, whose selects keep their kernel, 836 → 839. At c8 and c16 the capped card also holds a higher clock on the fix (c8 about 1,500 against 1,030 MHz at 72 W), since it moves fewer bytes. Before the rebase, 3 rounds over the site's whole curve (c4–c1024, pf4–pf1024, raw) moved nothing else outside ±1.2% apart from two points the line does not cause: c4 +3.7%, whose selects keep their kernel, and pf8 −2.3%, which is bimodal on this card. The alternative, `moe.mxfp4_grouped_reuse = 0`, gave c8 262 and c16 442, and cost c4 13%. Cross-model: gptoss-20b-mini c8 794 → 888 and a 32-expert MiMo-V2.6-Flash miniature c8 463 → 637, c4 309 → 331, the rest within spread. Greedy tokens are identical for raw (256 tokens) and pf8 (its one token) on all three models. At c8 and c16 every decode step changes kernel, and base against fix diverges a little further than one engine's reruns do (mean prefix share 0.36–0.57 against 0.45–0.97), while at c32 it stays inside the reruns' range. Tests, single-threaded on the L4: kernels-cuda `moe_select` passes the same 5 tests on both builds. The sixth, `the_routed_selects_answer_the_routed_dot`, fails identically on both (`Mx 8x400x4 false 320x1024`, every output the 0x7f7f fill). A fire trace shows every case before the failing one passing, the new case and the pipe kernel's included. The failing case is the first W4A8 case (#1274): off sm_120a its select declines, as the test expects, and the test still compares the output it never wrote. It is pre-existing and unrelated to this change. engine-cuda's GPU suite: pending.
